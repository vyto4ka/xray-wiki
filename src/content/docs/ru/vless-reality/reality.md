**REALITY** — протокол транспортной безопасности, созданный Project X как замена обычному :term[tls] на сервере. Он **полностью устраняет серверный TLS-отпечаток**, защищает от атак на цепочку сертификатов и позволяет вообще не покупать собственный домен и не выпускать сертификаты.

## Как работает REALITY простыми словами {#how-reality-works} :orig[reality: | REALITY 原理]

Обычный TLS-сервер вынужден предъявлять свой сертификат на свой домен, а при :term[active-probing]{активном зондировании} цензор легко видит нестандартную конфигурацию веб-сервера или свежий подозрительный домен.

REALITY работает иначе:

1. Вы выбираете реальный внешний сайт — например, крупный зарубежный ресурс с :term[tls]{TLS 1.3} и HTTP/2 — и указываете его в `target` и `serverNames`.
2. Когда к вашему серверу подключается **обычный браузер, сканер или цензор**, его `ClientHello` не содержит секретной метки REALITY. Сервер **прозрачно пересылает TCP-соединение на настоящий `target`**. Для проверяющего ваш IP-адрес на 100% ведёт себя как тот самый сайт — с его подлинным сертификатом и страницами.
3. Когда подключается **ваш клиент Xray**, он незаметно встраивает криптографическую подпись (на основе :term[x25519] и `shortId`) прямо в поле `SessionId` своего `ClientHello`, собранного через :term[utls]{uTLS} под браузер Chrome.
4. Сервер REALITY мгновенно узнаёт своего клиента и вместо проброса на `target` выдаёт ему **временный доверенный сертификат**, подписанный временным ключом сессии (и опционально постквантовой подписью :term[mldsa65]).

:::explain{ref="reality:~:REALITY 客户端可以完美区分" zh="三种证书状态处理"}
Клиент REALITY безошибочно различает три ситуации при подключении:

1. **Получен временный доверенный сертификат сервера** → рукопожатие успешно, открывается прокси-туннель.
2. **Получен настоящий сертификат целевого сайта `target`** (сервер отклонил `ClientHello` или трафик перенаправили на оригинал) → клиент не падает с ошибкой, а включает **режим краулера (`spiderX`)**, имитируя обычный заход браузера на страницы этого сайта.
3. **Получен чужой невалидный сертификат** (попытка активного перехвата MITM) → клиент отправляет `TLS Alert` и немедленно разрывает соединение.
:::

## Как выбрать хороший сайт для `target` {#choosing-target} :orig[reality:~:目标网站最低标准 | 目标网站选择标准]

Минимальные требования к чужому сайту для `target`:

- Поддерживает **TLS 1.3** и **HTTP/2 (`h2`)** (можно проверить командой `xray tls ping example.com`).
- Не делает принудительного редиректа с основного домена (например, если `example.com` редиректит на `www.example.com`, берите сразу `www.example.com`).
- Находится за пределами цензурируемой сети и не заблокирован у ваших пользователей.
- **Плюсы:** близкий по географии/IP к вашему серверу (ниже задержка при фоллбэке), включён :term[ocsp]{OCSP Stapling}, все сообщения после `ServerHello` шифруются единым блоком.

:::tip Альтернатива — «маскировка под собственный сайт»
Если у вас уже есть свой домен и локальный веб-сервер (Nginx/Caddy) на этом же VPS, можно указать `target: "127.0.0.1:8443"` (или локальный :term[uds]) и свой домен в `serverNames`. Внешний трафик при проверке будет открывать ваш собственный сайт-заглушку с минимальной задержкой.
:::

## Все параметры сервера (`realitySettings` в Inbound) {#server-params} :orig[#realityobject | 服务端 RealityObject]

```jsonc
"streamSettings": {
  "network": "raw",
  "security": "reality",
  "realitySettings": {
    "show": false,
    "target": "www.example.com:443",
    "xver": 0,
    "serverNames": ["www.example.com"],
    "privateKey": "<вывод xray x25519: PrivateKey>",
    "shortIds": ["", "0123456789abcdef"],
    "mldsa65Seed": "",
    "minClientVer": "",
    "maxClientVer": "",
    "maxTimeDiff": 0
  }
}
```

- **`target`** *(обязательно, ранее `dest`)* — адрес реального сайта или локального веб-сервера, куда уходит неподтверждённый трафик (например, `"www.example.com:443"`, порт или :term[uds]). :orig[~:target | target 目标地址]
- **`serverNames`** *(обязательно)* — массив допустимых доменов :term[sni], которые клиент может прислать. Подстановочный знак `*` не поддерживается. :orig[~:serverNames | serverNames 列表]
- **`privateKey`** *(обязательно)* — приватный ключ :term[x25519] сервера (генерируется командой `xray x25519`). Никогда не передаётся клиентам. :orig[~:privateKey | privateKey 私钥]
- **`shortIds`** *(обязательно)* — список разрешённых идентификаторов клиента в hex (`0-9`, `a-f`), чётной длины от 2 до 16 символов. Если добавить пустую строку `""`, клиент сможет подключаться без `shortId`. :orig[~:shortIds | shortIds 列表]
- **`xver`** — версия :term[proxy-protocol] (`0`, `1` или `2`) при пересылке на локальный `target`. Для чужих внешних сайтов всегда оставляйте `0`. :orig[~:xver | xver]
- **`mldsa65Seed`** — опциональный приватный seed постквантовой подписи :term[mldsa65] (`xray mldsa65`). Защищает от подделки сертификата квантовым компьютером. :orig[~:mldsa65Seed | mldsa65Seed 后量子签名]
- **`minClientVer` / `maxClientVer`** — ограничение версий клиентского Xray-core в формате `"x.y.z"` (пустая строка — без ограничений). :orig[~:minClientVer | 客户端版本限制]
- **`maxTimeDiff`** — максимально допустимое расхождение системного времени клиента и сервера в миллисекундах (`0` — проверка отключена). :orig[~:maxTimeDiff | 最大时间差]
- **`show`** — если `true`, выводит подробные отладочные сообщения REALITY в журнал. :orig[~:show | 调试输出]
- **`limitFallbackUpload` / `limitFallbackDownload`** — ограничение скорости для отклонённого фоллбэк-трафика (`afterBytes`, `bytesPerSec`, `burstBytesPerSec`). :orig[~:limitFallbackUpload | 回落限速]

:::warning Осторожно с `limitFallbackUpload` / `limitFallbackDownload`
Жёсткий фиксированный лимит скорости на фоллбэк-трафике сам по себе может стать заметным признаком прокси. Если включаете эти поля, значения нужно рандомизировать для каждого сервера.
:::

## Все параметры клиента (`realitySettings` в Outbound) {#client-params} :orig[#realityobject | 客户端 RealityObject]

```jsonc
"streamSettings": {
  "network": "raw",
  "security": "reality",
  "realitySettings": {
    "show": false,
    "fingerprint": "chrome",
    "serverName": "www.example.com",
    "password": "<вывод xray x25519: Password>",
    "shortId": "0123456789abcdef",
    "mldsa65Verify": "",
    "spiderX": "/"
  }
}
```

- **`serverName`** *(обязательно, в ссылке `sni`)* — один из доменов, перечисленных в серверном `serverNames`. :orig[~:serverName | 客户端 serverName]
- **`password`** *(обязательно, в ссылке `pbk`, ранее `publicKey`)* — публичный ключ :term[x25519], соответствующий серверному `privateKey`. Для клиента он фактически служит паролем доступа. :orig[~:password | 客户端 password / pbk]
- **`fingerprint`** *(обязательно для REALITY, в ссылке `fp`)* — профиль :term[utls] для имитации браузера (`"chrome"`, `"firefox"`, `"safari"`, `"ios"`, `"android"`, `"edge"`). По умолчанию рекомендуется `"chrome"`. :orig[~:fingerprint | uTLS 指纹]
- **`shortId`** *(в ссылке `sid`)* — один из идентификаторов из серверного массива `shortIds`. :orig[~:shortId | 客户端 shortId]
- **`mldsa65Verify`** *(в ссылке `pqv`)* — публичный ключ :term[mldsa65], парный к серверному `mldsa65Seed`. Если задан, клиент дополнительно проверяет постквантовую подпись сертификата. :orig[~:mldsa65Verify | mldsa65Verify]
- **`spiderX`** *(в ссылке `spx`)* — начальный URL-путь для встроенного краулера, который запускается, если сервер отклонил соединение и вернул настоящий сертификат `target`. Желательно задавать разный путь разным клиентам (например, `"/docs"` или `"/"`). :orig[~:spiderX | spiderX 爬虫路径]
- **`show`** — включает отладочный вывод REALITY на клиенте. :orig[~:show | 调试输出]
